# Backupper (CHATS-Sandbox)

A `PreToolUse` hook that captures what a tool call is about to destroy, **before** it runs, so the step becomes
undoable instead of refused.

## The idea in one paragraph

Cheap, mechanical tiers run on every call that can mutate something; one expensive tier runs only when it has to.
The agent is told to mark a step `[Backup needed]` when the step would destroy state the hook cannot see, and a
tool-less read-only checker is asked about unmarked calls, because the dominant failure is an agent that simply
forgets to mark. The hook never reads the agent's reasoning about *what* is at risk — it performs its own capture.

## Tiers, in order

| tier | what it does | cost |
|---|---|---|
| 0 | **policy rewrite** — `rm` becomes a move into a per-action trash dir (inode rename, size-independent); the reversal is recorded | µs |
| 1 | **targeted manifest** — `pip install` → `pip freeze`, `npm install` → `npm list`, env mutation → env dump | ms |
| 2 | **workspace snapshot** — a git shadow repo commits the workspace; plus an exact pre-image copy of a single file edited outside the workspace | ms |
| 3 | **backup subagent** — a one-shot LLM agent that captures state no local snapshot can reach (a remote database, a mailbox, a cluster object) and writes down how to restore it | seconds |

Tier 3 fires when the call touches state outside the workspace **and** tiers 1–2 did not already hold it **and**
(the agent marked the call **or** the read-only checker says it is not read-only). Tiers 0–2 never depend on the
marker, so a forgotten marker never costs the free protection.

## Install and run

```bash
npm ci && npm run build            # regenerates src/prompts.generated.ts from prompts/*.md, compiles to dist/
node dist/cli.js install claude-code   # or: codex | hermes  — writes the hook into the agent's config
node dist/cli.js config set mode checker
node dist/cli.js status
```

In this release the benchmark harness does all of the above for you; see `../QUICKSTART.md`.

## What lands on disk

Everything under `.chats-sandbox/` in the project root:

```
config.json                     effective config
declarations.jsonl              every [Backup needed] marker: surface, text, the action
checker.jsonl                   every read-only checker verdict and why
backup-timings.jsonl            added latency per action
subagent.log                    tier-3 spawn log
shadow-repo/                    the tier-2 git dir, shared by all actions
experiences/<server>.json       per-MCP-server capture playbooks (injected by the harness)
backups/action_001_<ts>/
  metadata.json                 the artifacts this action produced — the source of truth
  trash/…                       tier-0 soft-deleted files
  pip_freeze_*.txt, …           tier-1 manifests
  subagent_*.json               tier-3 result: what was captured, and the recovery commands
```

Action folders are created lazily: if no tier produced anything, no folder appears.
Retention: `maxActions` = 50, oldest pruned first.

## Prompts

Every prompt the plugin sends is a markdown file in `prompts/`, loaded through `src/prompts.generated.ts`
(regenerated by `npm run build`): the agent briefing, the backup subagent, the restore subagent, the read-only
checker, and the experience renderer. `../scripts/check_prompts.py` asserts the code and the markdown agree.

## Configuration

`node dist/cli.js config` prints the effective config. The settings that matter:

| key | default | meaning |
|---|---|---|
| `enabled` | `true` | master switch |
| `mode` | `"checker"` | `checker` (tiers 0–2 always, tier 3 on marker or checker verdict) or `off` (nothing runs, including deny rules) |
| `subagentEnabled` | `true` | tier 3 on/off |
| `subagentRunner` | `"claude"` | which agent CLI runs the backup subagent: `claude \| codex \| hermes \| openclaw \| openhands` |
| `subagentModel` | `"haiku"` | model tier for the claude runner |
| `subagentTimeoutSeconds` | `120` | warm backups take 20–35 s |
| `denyPatterns` | 8 rules | commands blocked outright (e.g. `rm -rf /`) |
| `maxActions` | `50` | action folders kept before pruning |
| `learnedReadOnlyEnabled` | `false` | in-session read-only patterns that skip a spawn; off by default |
| `verbose` | `false` | hook decisions to stderr |

Environment: `CHATS_SANDBOX_NO_HOOK=1` (recursion guard, set inside spawned subagents),
`CHATS_SANDBOX_STORE_DIR=<abs>` (store outside the agent's workspace),
`CHATS_SANDBOX_NO_REWRITE=1` (disable tier 0 where the host cannot apply `updatedInput`),
`CHATS_SANDBOX_READONLY_CHECKER=0|1` (force the checker off/on).

## Restore

`node dist/cli.js backups` lists actions; `restore <action>` replays tier 0–2 artifacts (trash, manifests,
shadow-repo commits) and, for tier-3 captures, hands the subagent's recorded recovery commands back. Restore
cannot undo what was never captured — a call that neither tier reached, or a capture the subagent got wrong.

## Limitations

1. The read-only checker is a tool-less LLM asked one question; it is wrong sometimes, in both directions.
2. Tier 3 depends on the subagent actually capturing the right thing. Its own failures are recorded in
   `subagent_*.json`, not hidden.
3. Tier 0 rewrites need the host to support `updatedInput`; where it does not (some SDK hook APIs), tier 0
   stands down and tiers 1–3 cover the action.
4. Latency is real: a tier-3 spawn blocks the agent for tens of seconds.
5. `subagentPermissionMode` defaults to `bypassPermissions` — the backup subagent may run anything.
